# 开发资料保留说明

正式公开仓库保留当前源码、固定知识底本、两册PDF、逐条审校、图像核对、研究实验记录及开发Git历史。普通用户的运行ZIP只包含运行、查证和连接所需内容，不包含完整开发审校档案。

本次保留核对见 `验收记录/开发资料保留核对-20261028.json`：3,345个文件逐一比较源文件与目标文件SHA-256，约1001.3MiB。源码、冻结知识、PDF另有发布验收，不依靠复制成功推断完整。

`archive/development-main` 保存原开发仓库71次提交。历史脚本、报告、旧环境路径与未实现目标按原样归档；不要直接运行历史清理、安装或发布脚本。当前产品以main分支README、发布状态和本版验收为准。

模型、依赖缓存和旧解压测试副本不重复加入Git。当前供用户下载和使用的运行包为0.4.2，包含本地Agent安装指南。

2026年10月29日，按用户要求清理正式仓库和原开发目录中的旧运行ZIP及配套校验文件，同时撤下GitHub v0.4.1的运行附件，并清理本次发布生成的临时ZIP副本。源码、版本标签、知识底本、知识归档、源代码备份及历史验收记录保留。详细删除清单和哈希见 `验收记录/0.4.2-旧运行包清理.json`。

历史验收回执记载的是当时实际完成的验证；旧压缩包的哈希继续保留用于追溯，不表示旧运行附件目前仍可下载。依赖旧基包的差异发布流程也仅作为历史记录，当前用户直接使用0.4.2完整运行包。

公开可下载不等于所有资料采用同一种开源许可。两册汇编PDF及引用内容的权利属于各自权利人，第三方运行时、模型、依赖以各组件许可证为准。本仓库没有把所有资料重新声明成统一许可。

删除旧开发目录前，确认GitHub的main、archive/development-main、版本标签和Release附件可访问，并保留正式仓库或完整离线备份。删除旧目录不在本次自动执行范围内。

`仓库文件清单.sha256` 从0.4.1开始只绑定Git版本管理内的文件，便于下载源码后独立核对。模型和运行时等交付文件由每个运行包内部的 `checksums.sha256` 及ZIP外部SHA-256单独绑定；本地依赖缓存不算独立交付资料。
