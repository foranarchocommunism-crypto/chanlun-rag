# 0.4.0 固定知识库正式版

本版交付一个可直接使用的本地证据检索服务。知识库固定，不再接收新知识；没有增量维护服务，也没有在线写入流程。

## 数据正确性

知识库、索引、模型、检索配置作为一整套版本使用。运行时拒绝 WAL、共享内存或写入日志状态，保持只读事务，阻止其他进程在会话期间提交修改。主文件或版本不匹配时明确报错；允许 Graph 降级也不能绕过数据错误。

正式包另有 snapshot.json 绑定知识库和清单，checksums.sha256 绑定全部发布文件。图谱的 3369 条 reviewed 命题、2611 条 pending 和 28 条 rejected 保留原状态。工程修复没有改变知识内容，也没有把待核内容改成已复核。

## 稳定发布与恢复

投影在独立临时目录构建，完成校验后才发布目录。向量检查点保存已确认长度和前缀哈希；中断后只保留通过哈希检查的前缀，重算未确认尾部。清单和检查点采用同目录临时文件、文件刷新和替换，未完成的临时文件不会成为正式清单。重复执行已成功的构建会校验并复用产物。

故障验收使用真实构建脚本和本地模型，并在检查点、投影清单、最终清单三个位置强制终止进程。它证明本机 Windows 下的进程中断恢复；不冒充真实断电、磁盘损坏或独立机器验收。

## Graph 的定位

保留带原文依据的定义定位和关系追查。普通图扩展与实验配置共用实体触发、节点、扇出、读取次数、证据检查和时间限制。旧配置的排序行为保留以控制回归，新增候选的准入方案可通过 hybrid-graph-v2-rerank 显式选择。

一跳、二跳共同竞争，没有二跳专用名额、下限或特殊重排文本。240 道已使用过的开发题只能用于对照，不构成独立语义验收。Graph 的整体召回优势须由报告中的实际差异判断；运行了图遍历不等于增加了正确证据。

## 调用与追踪

CLI、JavaScript 和 MCP 共用 RetrievalService。结果含生效参数、代码和数据指纹、实际通道、降级原因及排队时间；--trace 额外返回有预算限制的各阶段候选与排名。向量命中窗口和原始理由在融合后保留。

单服务最多接受 8 个正在执行或等待的请求，等待超过 30 秒明确失败。此限制管理队列，不宣称能抢占正在执行的本地模型运算。

检索分数表示相关性，不表示事实概率。命题适用条件、例外、来源角色和歧义随证据保留，最终答案仍由调用 Agent 判断。

## 实现依据

- [SQLite WAL 官方说明](https://www.sqlite.org/wal.html)：WAL 是数据库状态的一部分，静态只读发布应先关闭写入并使用 DELETE 模式；本服务拒绝活动或休眠 WAL，不通过 immutable 参数忽略未合并数据。
- [lowdb](https://github.com/typicode/lowdb)：本次核对为 MIT、22,586 stars、未归档；借鉴临时文件后替换的设计。其 [Windows 并发写问题](https://github.com/typicode/lowdb/issues/610) 有用户反馈，说明固定临时名和并发写要额外处理。没有引入 lowdb 依赖。
- [npm/write-file-atomic](https://github.com/npm/write-file-atomic)：ISC，stars 未达 500，作为补充参考；核对文件刷新、唯一临时名和替换顺序。当前实现使用 Node 内置文件 API、唯一临时名及构建锁，没有直接复制外部实现。

目录替换和文件刷新不能推导出任意硬件断电下的持久性保证。验收记录只陈述已经运行的场景。
