# 0.4.0 中的可选 Graph 候选准入

新候选准入方案通过 hybrid-graph-v2-rerank 显式选择，默认深度为一跳；需要时可明确请求二跳。它与默认策略均具备受控回退和有界遍历。默认排序保留已经验证的定义定位行为；本说明不宣称可选策略具有整体质量优势。

## 使用与边界

```js
const packet = await service.retrieve({
  query: '背驰与买卖点有哪些关系？',
  profile: 'hybrid-graph-v2-rerank',
  allowDegraded: true
}, { signal: abortController.signal });
```

```powershell
.\chan-kg.cmd retrieve "背驰与买卖点有哪些关系？" --profile hybrid-graph-v2-rerank --allow-degraded
```

JS、CLI、MCP 使用同一 RetrievalService。`allowDegraded` 默认为 false；设为 true 后，Graph 缓存准备、遍历、锚点选择、路径验证或包装的局部失败会撤销整段 Graph 贡献，返回原先的文本召回结果，并在 runtime 记录实际通道与原因。严格模式返回错误。数据不匹配、源库损坏、无效参数与调用方取消始终报错。原有默认 Graph 策略也获得这一错误边界。

实验配置默认重排预算 48：保留文本前 40 条，Graph 最多补 8 条；这 8 条由一跳和二跳共同竞争，补入不等于最终排在前面。所有候选均仅使用自身文本、前提和例外作为重排输入。二跳没有专用通道、保底名额、优先分数或拼接提示。评分是相关性，不是正确概率，也不把路径当成作者的传递推论。

旧请求的预算 20、40 仍有效；它们没有额外 Graph 名额，runtime 明确显示原因。44 表示最多补 4 条；候选总预算更低时以更低值为准。不会偷偷突破调用方限制。

Graph 只在问题明确出现实体名称、别名或指定 conceptId 时展开。无锚点、原文模式、深度为 0、路径预算为 0 都会跳过。一跳和二跳共用最多 20 条路径的预算，根据同一规则排序；第二跳可以一条都不入选。根节点最多 8 个，每节点每层最多选择 4 个邻居、读 32 条邻接，最多访问 64 个节点、读取 512 条边、核对 1024 个支持项，100ms 合作式截止。该截止会在检查点终止同步工作，不是操作系统级抢占。

每一步返回关系原方向、关系类型、支持原文和状态。反向遍历只表示相关联。完整路径需要的支持候选整体进入重排；空间不足则整组推迟。主结果、争议组、辅助原文与路径共用 contextBudget；辅助原文不计入主结果的召回成绩。放不下完整路径时给出逐条关系的继续查询入口，不返回半条“完整路径”。

## 效果证据

240 道题属于已经看过的开发题，不能充当新的独立语义验收。正式版重新对照文本 40、文本 48、一跳和二跳自然竞争，具体数字见发布仓库的 Graph 价值报告与原始指标。真实原书在 60,000 字符上下文中存在完整路径无法装入的情况，放不下时整条推迟，不抢占主结果来制造成功率。

50 组候选材料经用户判断：转述准确，但主要是围绕同一概念的不同内容，缺少必须结合两份原文的问题。学生作答已取消；这些材料没有作为已通过的两跳金标。新准入策略保持默认关闭，二跳专项提升门槛已取消。
