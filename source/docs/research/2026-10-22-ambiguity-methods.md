# 含糊、表面冲突但有信息价值的领域知识：RAG + KG 可迁移机制

研究日期：2026-10-22。范围：方法研究与迁移建议；未读取、修改或导入图谱数据库，未修改查询代码。任务提供的背景为 473 条 reviewed 显式歧义、2611 条 pending；这些数量只作为问题背景，本笔记未做实时审计。

核心建议是保留可检索的原文信息，并把“原文确实说过什么”“在什么条件下成立”“有哪些解释”“当前证据能否区分解释”分别表示。含蓄表述可以提出可检验的解释假说，不能直接变成作者命题；原文之间也可能存在真正冲突或源文缺陷。本笔记提供的论文和标准均未验证缠论知识，也未证明本项目中的任何具体矛盾一定可消解。

## 2. 机制一：把一个含糊问题展开为有限个有证据的解释分支

AmbigQA 的可迁移价值是把“多个合理答案”作为任务目标，并把每个答案对应的消歧问题一并输出；ASQA 进一步要求长答案说明这些解释之间的关系。对应的评价也不能只看某一个答案是否命中：AmbigQA 包括答案 F1 和问题改写评价，ASQA 的 DR 组合 Disambig-F1 与 ROUGE-L。[AmbigQA 原文 §2](https://aclanthology.org/2020.emnlp-main.466.pdf)、[ASQA 原文 §4](https://aclanthology.org/2022.emnlp-main.566.pdf)。

**本项目设计建议，尚未在本领域验证：**查询首先寻找几个由现有证据支撑的解释，而不是先选最像的一个命题，再让模型补齐省略条件。一个解释分支至少给出：重写后的问题、相关术语含义、明确条件、所用证据、尚缺信息。限制分支数量可以控制回答长度，但不能把“只显示前三项”写成“只有三种解释”。

分支内部再区分：

- **原文支持的解释**：消歧条件有明确语句或可核查上下文依据。
- **解释假说**：某条件能解释两段文字为何不同，但该条件没有被作者直接说出；标明提出者、推导用到的证据及会否证它的材料。
- **仍无法区分**：可定位差异，但原文不足以确定作者用意；保留缺口。

一个中性的示意输出可以是：“若这里的‘同级’指对象 A 的级别，则证据 E1 支持解释一；若指观察尺度，则 E2 与解释二相容。第二个条件目前只是解释假说；现有原文不足以裁定。”这不是缠论事实示例，也不声称相容即被原文蕴含。

**限制：**AmbigQA/ASQA 的多答案一般有可确定的参考答案。作者文本的含蓄性还可能来自比喻、术语漂移、笔误或根本欠定义，所以“列出解释”只是保存不确定性的回答方式，不构成消歧成功的证据。

## 3. 机制二：把条件化命题作为单位，给同一命题保留不同来源和语境

W3C 的 n-ary 模式通过关系实例记录一条关系的多个参与者及附加属性；PROV-O 的 qualified relation 可以补充派生、活动和责任者等细节。另一个重要边界是 RDF reification：描述某个三元组的记录并不蕴含该三元组为真。[W3C n-ary 模式](https://www.w3.org/TR/swbp-n-aryRelations/)、[PROV-O §3.3](https://www.w3.org/TR/prov-o/#description-qualified-terms)、[RDF 1.1 Semantics 附录 D.1](https://www.w3.org/TR/rdf11-semantics/#reification)。

**本项目设计建议：**无需改用 RDF 或引入三元组数据库；可在 SQLite 的命题和证据旁保留同样的语义区别。以下是候选数据合同，不是已检查现行 schema 后得出的迁移脚本。

| 建议记录的信息 | 用途 | 防止的误判 |
|---|---|---|
| 原文跨度、页码、稳定证据 ID、说话者身份 | 固定可复查的文本锚点 | 把整理者、读者或后加说明当成作者 |
| 命题内容、极性、对象与术语指向 | 明确究竟支持什么 | 同一词形自动合并成同一含义 |
| 明示条件与例外 | 限定应用范围 | 局部技术解释泛化为普遍定理 |
| 条件未知项 | 表示原文没有交代什么 | 把未写出的条件默认为不存在 |
| 解释假说及其提出者 | 保存可能有用的解释 | 机器补出的条件成为作者原话 |
| 引文、概括、推导等派生类型 | 保留形成过程 | 来源归属被误当成逻辑蕴含 |
| review 状态与问题是否解决的状态 | 两个维度分别查询 | 已复核的歧义被写成已消歧 |

时间是语境字段；“后写”本身不足以推出“修订早文”。PROV 的 revision 也表达明确派生关系。本项目应要求“修订、限制、补充”关系附上具体文字依据，而不是从日期自动生成。这是本项目的证据政策建议，不能说成 W3C 为缠论规定了修订准则。

**限制：**表示结构只能让缺失条件可见，不能自动找回作者没有写出的条件。也不应仅因两个命题的条件字段不同，就认定二者不冲突：差异可能是提取错误或同义表达，需要审校。

## 4. 机制三：按冲突成因选择回答行为，保留“原因未知”

DRAGged 的辅助研究将无冲突、互补信息、相互冲突的观点/研究结果、信息过时、错误信息分开，并将类别映射到不同回答行为。其 CONFLICTS 有 458 个实例；最高类别预测准确率为 65.3%，而提供或预测类别有助于回答行为。这里的数字属于其特定基准，且该工作本次未核实正式接收。[预印本 §2–5、表 2、4、5](https://arxiv.org/pdf/2506.08500)。

结合正式的多解释任务和冲突基准，本项目可以建立以下**领域适配分类**。这张表是本笔记提出的操作分类，不是照搬某篇论文，也不是对 473 条歧义完成重标注后的结果。

| 候选成因 | 足以进入该类的依据 | Agent 适合的回答 | 尚不能做的判断 |
|---|---|---|---|
| 条件或对象不同 | 原文能指出不同适用对象、层级、阶段、前提或例外 | “在 C1 下为 A，在 C2 下为 B”，各引证据 | 仅凭能编出 C1/C2 就宣称已解决 |
| 多种合理解释 | 同一表述支持多个可辨认指向，或问题欠具体 | 分别重写问题，给出解释和缺少的限定 | 把所有不同答案写成互相否定 |
| 解释假说未定 | 有可解释差异的候选条件，但缺少直接依据 | “一种可能解释是 H；它需要额外假设 X” | 将 H 发布成作者明说 |
| 真正冲突候选 | 对象、谓词、极性和条件已对齐后仍不相容 | 列出双方原文、冲突位置和未决问题 | 用权重、票数或模型记忆强选一方 |
| 源文、身份或提取缺陷候选 | OCR、断句、图号、说话者、缺页等有具体异常 | 展示异常并要求回看原页；保留暂不可用原因 | 用“作者意会”掩盖可纠正的文本错误 |
| 原因未知/证据不足 | 当前资料无法支持上面任何一种确定判断 | 说明可确认内容与无法裁定处 | 把未知默认归到“作者其实一致” |

**限制：**“错误信息”在已有金标准的基准中较容易定义，在固定作者文献中可能没有独立真值。没有足够证据时应使用“疑似源文缺陷”或“未决冲突”，不能让模型凭常识为作者判错；同样不能预设作者无误而无限补条件。

## 5. 机制四：聚合的是带归属的证据分组，而不是无来源的平均答案

MADAM-RAG 在单文档回答后由 aggregator 整合，并用多轮交互处理歧义、错误信息和噪声。其严格准确率要求包含全部 gold answers，且不混入错误答案；论文也观察到支持文档分布失衡会使任务更难。[论文 §3–6](https://arxiv.org/html/2504.13079v2)、[作者实现](https://github.com/HanNight/RAMDocs)。ConflictingQA 的正式研究另提示：模型认为“令人信服”的文本特征不能直接代替可靠来源审查。[ACL 2024 原文](https://aclanthology.org/2024.acl-long.403/)。

**可迁移的是分来源、分解释再聚合的结构，不必照搬多代理辩论。**可以用一次模型调用或确定性程序构建证据包：

1. 初始召回按词义、对象、条件、来源角色分组；向量相似度只能是召回信号。
2. 对每个分组读取原文，记录支持哪一解释、限制哪一解释、与哪一解释不相容，以及未知点。
3. 一旦存在冲突组，定向补取冲突另一侧及其邻接的前提、例外、答疑上下文；保留检索预算与截断信息。
4. 汇总时先保留每个分组的结论与引用，再说明组间关系；不把重复转载、近重复摘录或同一来源的多条切片当作独立投票。
5. 输出“已找到什么”与“此次检索未找到什么”。未检出反例不能写成不存在反例。

这些步骤是建议的轻量工程方案。论文中有 aggregator 的收益，**不等于**本笔记这个单调用/确定性版本已被同样验证。MADAM-RAG 的多代理也不是互相独立的知识来源；同模型重复同一解释不会增加原文证据数量。

**限制：**RAMDocs 主要是构造的混合冲突任务，且评价能访问 gold labels。迁移时不能把数据文件里的 correct/misinfo 标签能力误认为线上系统已具备，也不能把“多数文档支持”直接改写成“理论成立”。

## 6. 机制五：局部保留支持与否定，限制跨冲突传播

Belnap 的动机是避免数据库的小范围不一致导出无关结论；FDE 可以区别 true、false、both、neither。后续 AAAI 论文也说明，条件联结词与计算推理需要额外设计，并不是加四个状态名就实现完整推理系统。[Belnap 出版原文摘要](https://link.springer.com/chapter/10.1007/978-94-010-1161-7_2)、[Sutcliffe et al. 原文 §1–2](https://cdn.aaai.org/ocs/17599/17599-77711-1-PB.pdf)。

**适合本项目的最小借鉴是两个证据集合，且限定在相同语义与条件范围：**

| 对命题 P 的支持集合 | 对命题 P 的明确否定/不相容证据集合 | 可显示的信息状态 |
|---|---|---|
| 非空 | 空 | 当前有支持，未检出相反证据 |
| 空 | 非空 | 当前有反向证据，未检出支持 |
| 非空 | 非空 | 双方证据并存，局部冲突未决 |
| 空 | 空 | 当前证据不足 |

这里的状态是“当前证据包状态”，不能直接命名成现实真值。不存在证据不等于否定；“否定 P”也必须与 P 的对象和条件对齐，不能用不相关段落充当反证。

最小传播策略可以是：未经人工确认的解释不生成新的正式作者边；从一组冲突出发的回答只返回冲突、条件和引用；其他无关、已获支持的命题仍可检索。关系路径若依赖未决假说，整条路径明确标成条件推导，给出所依赖假说。这样可以限制冲突影响范围，且不要求安装完整的 paraconsistent reasoner。

**限制：**上述政策只防止系统自己把冲突任意转成肯定结论，不保证自然语言推导的完备性或形式逻辑一致性。两条不同的条件规则并不自动构成 P 与非 P；若未来引入规则引擎，必须另行定义同一性、否定、条件与推导语义，并验证跨规则行为。

本阶段没有必要把非单调/defeasible reasoning 变成依赖项。只有当审校者已经给出了明确、有限的例外与优先关系，且确有自动规则应用需求时，才有理由评估对应引擎；不得让“更具体优先”“较新优先”替代文本证据。这是范围判断，尚未开展规则系统选型或性能比较。

## 7. 机制六：同时评价多解释覆盖、冲突定位和拒绝过度结论

MAGIC 把检测冲突与定位冲突分开；定位评分要求找全冲突位置，且由研究人员人工评分，模型在多跳场景仍有明显困难。它揭示的是需要检查具体证据链，不能仅检查模型说没说“有矛盾”。[MAGIC 原文 §4–5、Limitations](https://aclanthology.org/2025.findings-emnlp.466.pdf)。2026 年的 CMC-Bench 又提醒，拒答和无依据生成应该分开衡量；该工作是跨模态工作坊研究，适用于未来图文冲突用例设计的启发，不是本领域视觉验证。[CMC-Bench 正式记录](https://aclanthology.org/2026.magmar-main.3/)。

**建议的本地人工测试合同：**只在获准试验后，从现有材料建立小规模、版本固定的独立题集；当前笔记不创建题集、不重审全库。题目应包含普通明确命题作为对照，以及条件差异、多解释、未决冲突、源文缺陷、证据不足等真实案例。每例标注“目前人工可以支持的判断范围”，允许多标签和无法确定，不要求审校者替作者补出唯一真理。

| 要测的能力 | 建议核对项 | 与论文方法的关系 |
|---|---|---|
| 信息保留 | 应返回的有用原文、条件、例外和解释分支是否被召回 | 借鉴 AmbigQA/ASQA 的多解释覆盖思想 |
| 出处准确 | 引文是否来自指定说话者、页码及跨度；引用是否支持相邻结论 | 来源合同与人工蕴含核查，不能仅检查引用存在 |
| 冲突检测和定位 | 是否误报；是否漏掉另一侧；是否指出具体不相容字段或最小证据路径 | 借鉴 MAGIC 的 ID 与 LOC 分离，但不声称复用其分数 |
| 假说诚实度 | 隐含条件是否标成假说，是否说明额外假设 | 本领域新增的工程验收项 |
| 行为合适 | 条件分开、并列解释、展示冲突、局部拒绝是否与人工判定相符 | DRAGged 的辅助分类行为思路，不把它当正式验证结论 |
| 过度确定性 | 是否将未检出说成不存在、将解释说成作者明说、将 pending 说成已核实 | 本领域新增的工程验收项 |
| 有限拒答与有用性 | 能回答的部分是否保留；无法裁定部分是否清楚限定；无依据新结论单独计数 | 与 ASQA 的覆盖及 CMC 的拒答/生成分离思路相容 |

检索和生成应分开评价。召回了冲突两侧并不证明答案正确；模型输出“谨慎措辞”也不证明有证据；图结构通路存在更不证明自然语言蕴含。整体正确率之外，必须保留各类失败的分母、原例与人工判定，不用一个综合分掩盖“少说而看似正确”的退化。

## 8. 对当前系统的迁移顺序与交付边界

以下为建议顺序，不是本次已完成的开发：

1. **先定状态含义。**保留现有 review 状态，另增加或输出是否含糊、解释是否未决、是否有局部冲突等信息。具体字段须先与现有 review 合同核对，不在本笔记中倒推或改写历史 reviewed 的含义。
2. **先增强检索结果的证据包。**为命中歧义附上原文、明示条件、关联解释和反向证据；pending 保留待核身份。哪些场景允许检索 pending 由产品显式策略控制，不默认混入正式已复核结论。
3. **先做回答分支和不确定性展示。**为每个分支展示“依据—条件—缺口”；局部不能裁定时，仍返回可确认的信息。模式可用同一个 Agent，不依赖多代理辩论。
4. **再做小样本人工比较。**与当前单分支问答比较有用信息覆盖、错误确定性、引用准确率和时间/成本；保留失败例。获得真实收益后再讨论是否增加自动冲突提议或规则推理。

本次研究的可交付结论是：上述原始研究和表示规范为“保留信息、条件化、保存出处、并列解释、暴露局部冲突、限制过度结论”提供可迁移机制；没有证据可以跳过本领域人工审查，也没有证据证明把所有歧义一律消歧或一律过滤会达到用户目标。对于作者意会而未写明的内容，系统可以保存解释空间，但无法从方法论文中取得作者意图的真值。
