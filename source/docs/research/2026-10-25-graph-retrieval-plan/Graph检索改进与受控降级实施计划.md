# Graph 候选准入、两跳检索与受控降级实施计划

版本：方案 v1，2026-10-25。状态：研究与方案已完成；生产改造和新验收尚未执行。适用对象：当前 chan-kg-agent 0.3.0 的共享 RetrievalService、CLI、JavaScript API 与 MCP。

执行补记（2026-10-25）：上句是方案冻结时的历史状态。工程实现与候选包已执行，当前结果见同目录《实施执行报告.md》。用户已取消学生作答，确认本批关系主要是共同概念下的不同内容；未形成新的独立两跳验收题，实验策略保持默认关闭。原方案和 acceptance-plan.json 保留为审计依据，不改写成“全部通过”。

最新决定：用户要求二跳自然竞争，已取消二跳路径预留、候选保底和特殊重排输入。下文的 12/8、二跳预留 4 个新增候选及二跳专项提升门槛是被取代的原设计，不能用于当前 rc.2。当前规则和替代测试见 evaluation/graph-v2/natural-competition-decision.json；这项最新明确决定优先于原方案。

本次目标有两项：让 Graph 找到的有效新证据有机会影响最终结果；让可选 Graph 阶段的局部故障不会在允许降级时中断原本可用的文本检索。实现是否成功，分别以真实证据收益和故障注入后的等价回退证明。

## 1. 决策与证据边界

采用“保留文本候选 → 有界图扩展 → 独立增补准入 → 联合重排 → 完整路径包装”，并为整个可选 Graph 阶段设置提交/回退边界。

当前不把调大 Graph RRF 权重作为主修复。原因是现有参数已经使纯 Graph 新候选不可能进入满额 Top100，而提高权重也不能保证候选正确。详细推导、论文、固定提交的开源代码与 Issue 核查见[研究依据与取舍](C:/Users/13240/Desktop/RAG/chan-kg-agent/docs/research/2026-10-25-graph-retrieval-plan/研究依据与取舍.md)和[sources.json](C:/Users/13240/Desktop/RAG/chan-kg-agent/docs/research/2026-10-25-graph-retrieval-plan/sources.json)。

本轮实测又排除了一个容易误用的方案：固定 40 个重排名额时，36＋4、32＋8 在旧 240 题标注下分别出现 1 题、3 题候选证据覆盖退步，均没有改善。保留 40＋4/8 没有挤掉原候选，但也没有增加旧标注覆盖。因此：

- 优先验证“40 个文本候选＋最多 8 个 Graph 增补”，总重排上限 48。
- 40＋4 是预先登记的成本备选；36＋4、32＋8 仅作为消融对照，不作为上线默认。
- 新增候选数量、二跳次数、单元测试通过均不能替代检索质量收益。
- 只有新的两跳专项集、普通查询回归和资源门槛一起通过，才启用新默认。
- 受控降级可以先独立交付；Graph 质量改造未达标时不阻塞可用性修复。

本轮未修改生产代码、图谱、向量索引、模型和正式交付包。已有 47 项测试通过属于前次审查证据，不等于新方案通过验收。

## 2. 实现边界与模块改动

继续使用现有 SQLite 图谱、词法与本地向量检索、本地交叉编码器。保留 reviewed/pending/rejected、作者来源、条件、例外、歧义和证据续取语义。Graph 路径表达有来源支持的关联，不自动推出传递性结论。

## 3. 候选准入：确保新证据真的送进模型

**3.1 保留原文本检索基线。**

先完成原词法/向量检索和文本 RRF，得到有序文本集合 B，并保存不可变快照。默认取 B 的前 40 个作为受保护候选。此时尚未加入 Graph 重加权、定义锚点、路径或置顶状态。

同时保存完整词法、向量候选并集 U，严格区分：

- graph_only：不在 U 中，是图新增的检索候选。
- graph_rescued：在 U 中，但不在受保护的文本重排集合中。
- already_in_base：已经在受保护文本集合内，只附加路径和来源，不重复占位。
- definition_anchor：定义规则选出的候选，独立计数，不能混报成一般两跳收益。

**3.2 Graph 增补绕过原 Top100 截断，直接参与重排输入构造。**

不能先把 Graph 列表再次低权重 RRF 截到 100，再期待后续挽救。新准入函数直接接收 B、Graph 支持路径、定义锚点及预算：

1. 受保护文本集合先入选。
2. 定义锚点最多 2 个；已存在则不占新增名额，新加入者计入 Graph 的 8 个名额。
3. 剩余增补名额优先为完整二跳路径组预留最多 4 个不同命题的位置；再接纳一跳组，并回填尚未用完的名额。
4. 每条二跳组包含两条边各自选择的支持命题；若其中一个已在文本集合中，只消耗另一个位置。不能只保证终点进入，而把唯一桥接证据漏掉。
5. 在相同跳别/资格下，先考虑 graph_only，再考虑 graph_rescued；按明确查询锚点、文本种子排名、路径长度和稳定 ID 排序，并轮流覆盖不同根实体。所有信号可追踪；不把它们称为真值置信度。
6. 一个路径组装不进余量时，整组延期；尝试后续能装入的组。所有 ID 去重，无足够图候选时实际模型输入回落到文本数量，不为凑数补入弱相关 Graph 候选。
7. 对最终最多 48 个命题执行一次现有交叉编码器重排，再按既有精确 ID 和合法定义锚点规则处理。一般 Graph 候选没有最终结果保底名额。

候选池尾部可以保留文本 B 的其余项供既有流程使用，但送入重排的前部必须由准入函数显式构造。需要检查实际 `reranker.score()` 接收到的 ID，而不是只检查“融合候选列表含有新 ID”。

**3.3 参数契约。**

新配置的默认总重排上限为 48，其中保护文本 40、Graph 增补最多 8。新增允许值 44、48；20、40 保持可请求。总量受请求与候选池上限共同约束：

```text
R = min(request.rerankBudget, request.candidateBudget)
textProtected = min(40, R)
graphAllowance = min(profile.graph_additions_max, R - textProtected)
```

|请求容量 R|受保护文本|最多 Graph 增补|说明|
|---:|---:|---:|---|
|20|20|0|尊重旧的低预算请求，明确报告无增补空间|
|40|40|0|保留原文本集合，不暗中挤占或超预算|
|44|40|4|预登记的成本备选|
|48 或以上|40|8|建议默认，仍需资源与质量验收|

20/40 并不保证新图候选进入重排；轨迹必须报告 `graph_admission_budget_exhausted`。调用方需要新的 Graph 增补能力时使用 44/48。候选池小于重排预算时取较小值，不能偷偷超出请求。

本次收益承诺针对默认带重排的检索链路。无重排的 `hybrid-graph` 保留可用性与路径行为，但不宣称同样的新候选排序收益；应在结果中明确是否执行了重排。若重排器失败，依原 allowDegraded 策略处理，不将 Graph 配额当作最终排序分数。

## 4. 两跳：分层预算、完整证据和确定性停止

建议新配置使用最大深度 2，默认路径预算仍为 20。由请求的 graph profile 开启图阶段，不新增在线 LLM 路由器。source 模式、深度 0、预算 0 明确跳过；精确命题 ID 直接命中时可跳过扩展并保留原行为。新策略要求至少一个查询明确提到的现有实体/别名，或调用方给出的合法 conceptId，作为路径根；没有根时记录 skipped/no_query_anchor，继续文本检索。第一跳有合格新前沿，且请求允许二跳，才进入第二跳。

先完成文本检索，再把前列命题中的概念与查询明确提到的实体/别名、合法 conceptId 对齐；显式实体可补充为根，最多保留 8 个不同根实体。新准入路径必须从这些查询根出发，不能仅凭弱相关文本命中的任意概念扩散。该保守门槛不依赖新增模型或未经校准的相似度阈值；代价是缺少现有实体名称/别名的纯改写问法暂不触发新图扩展，仍由文本检索服务，需单列这类漏触发率。短名称、多义实体和领域外查询列入负例，不能把字面命中当成语义置信度。

拟冻结的初始预算：

|资源|初值|语义|
|---|---:|---|
|最大深度|2|不得越界|
|不同根实体|8|按稳定顺序截断并记录|
|每个节点每一层选出的邻居|4|不同邻居，重复支持命题不增加扇出|
|每个节点检查的邻接记录|32|避免为选择 4 条边扫描无限邻接表|
|每请求访问不同节点|64|包含根实体|
|每请求检查边记录|512|计入不合格和重复记录，避免跳过项不计成本|
|每请求检查支持命题|1,024|防止单条关系有大量支持命题而失控|
|第一跳输出路径|12|默认总预算 20 时|
|第二跳输出路径|8|先保留，不被第一跳提前借走|
|Graph 阶段协作式截止时间|100 ms|使用单调时钟；超时作为局部失败处理|

自定义路径预算 B≥2 时：二跳预留 `max(1, floor(0.4*B))`，一跳使用余量。B=1 时有效深度降到 1 并记录原因；B=0 跳过。先让每一层使用自己的预算，第二层尝试完成后才允许回收未用名额。所有硬上限同时生效，触及节点/边等上限时不能以“回收余量”为理由继续访问。

每条输出记录代表一个不同的关系路径，最多选一组规范支持命题；同一关系有 20 条支持命题不能耗掉 20 个路径名额。按 review 状态、已在文本基线中的支持、稳定 ID 选择规范支持，保存其余支持 ID 供续取。研究模式允许 pending 的既有规则保持不变，不能混入 reviewed 输出。

遍历按前沿轮流访问邻接记录，避免一个超级节点吃掉全部检查预算。每条路径维护节点集合，拒绝 A→B→A 的重复节点路径；不同路径可以共享节点，避免全局 visited 集合误杀合法桥接。反向访问仍保存原关系方向和 association_only 语义。

采用受版本绑定的邻接索引，避免每个查询排序全图。索引准备、遍历、支持命题选择都位于可回退的 Graph 边界内。同步循环中定期检查计数和单调时钟；仅使用 Promise.race 不能中断同步循环，不作为截止机制。这里保证的是已知循环的受控停止，不承诺中断任意挂死的外部同步代码。

**完整路径结构。**

新增 `steps[]`，每一步携带 relation_id、原方向、遍历方向、关系类型、review 状态、support_claim_id 和 evidence_ids；保留完整 concept_path、relation_path、seed_claim_id。第二跳不得只记录末边证据。

最终终点命题通过重排进入主要结果后，路径包装可附带必要的桥接命题及其条件/例外和来源；这些作为辅助证据单独计数，不伪装成额外的主要 Top20。每个请求最多附带 8 个不同辅助桥接命题，全部受同一 contextBudget 约束。整条路径装不下时，整条路径延期并提供续取信息，不能返回“看似完整”的残缺链；终点命题可作为独立的有来源命题保留，但不计作完整二跳成功。

## 5. 受控降级：整个可选 Graph 阶段一次提交

在进入 Graph 阶段前保留文本排名快照。Graph 使用局部变量构造路径、锚点、重加权和增补计划；验证完成后一次性提交，禁止逐步修改共享 ranked、runtime.actual_channels 或已包装结果。

边界覆盖：可选邻接缓存准备 → 图扩展 → 支持路径校验 → 定义锚点 → 候选增补方案。图路径专用包装使用另一局部草稿；失败时同样丢弃全部 Graph 影响，使用已保留的文本结果完成证据包。知识库版本和规范证据完整性检查始终先于可选边界。

|情况|allowDegraded=false|allowDegraded=true|
|---|---|---|
|可选图视图不可用、遍历异常、合作式截止超时、图结果结构校验失败|明确错误码、stage=graph|丢弃全部图增量，执行文本基线剩余步骤|
|正常没有图路径|成功，graph=empty|同左，不标 degraded|
|达到正常路径/节点/边预算|成功，graph=budget_exhausted，说明截断|同左，不当作运行异常|
|主动 source/深度 0/预算 0 跳过|graph=skipped|同左|
|非法请求、规范知识库损坏、证据引用不存在、版本不匹配|失败|仍失败，不能以图降级掩盖完整性问题|
|调用方取消请求|传播取消|传播取消，不启动备用流程|

错误建议为 GRAPH_UNAVAILABLE、GRAPH_EXECUTION_ERROR、GRAPH_TIMEOUT、GRAPH_OUTPUT_INVALID；原始 cause 留在内部诊断，不泄露堆栈到普通证据内容。未知错误只有在可选 Graph 局部边界内才能归一为 GRAPH_EXECUTION_ERROR；不得包住整个检索函数吞掉任意异常。规范语料本身缺少引用是全局完整性错误；规范语料有效、但可选 Graph 算法生成了错误 ID/结构，属于 GRAPH_OUTPUT_INVALID，两者必须分开验证。

回退基线采用进入 Graph 前的文本 40（低预算时相应减小），继续同一个重排器。不得重新做词法检索、向量查询或再次计算 query embedding。图阶段在重排前失败时，备用路径只有一次重排调用。若图专用包装在重排后失败，可复用已算的受保护文本分数重新排序；必须验证与文本单独重排在约定容差内等价，并测试排序稳定性。

Graph 的异常不自动重试。确定性的本地图错误重试只增加延迟；修复或语料版本变化后再重建可选缓存即可。不得把错误导致的半成品缓存当作成功缓存发布。

轨迹至少包含：requested_profile、effective_pipeline、actual_channels、degraded、degradation_reasons，以及 graph 的 status/reason、attempted_depth、completed_depth、attempted/committed 路径数、各预算使用量、超时/截断原因、被准入的 graph_only/graph_rescued/anchor 数、实际送入重排数量与最终主要结果中的数量。

Graph 失败时 committed_paths=0，无 graph_definition_anchor、无图置顶、无二跳辅助证据；actual_channels 只列本次最终结果实际使用的通道。空、跳过、正常截断和失败必须可区分。图成功但没有改变候选时可记录 evaluated，但不得报“新增候选参与排名”。

## 6. 可执行验收用例

机器用例清单见 [acceptance-plan.json](C:/Users/13240/Desktop/RAG/chan-kg-agent/docs/research/2026-10-25-graph-retrieval-plan/acceptance-plan.json)。以下均为实施后必须新增的验收，当前状态是 planned。

|组别|最小构造/动作|通过条件|
|---|---|---|
|A1 候选截断|100 条词法＋100 条向量背景；Graph 独有命题 G 不在两通道并集|G 在准入记录中，并真实出现在 reranker 输入；不能只留在 Top100 尾部|
|A2 真实模型贡献|隔离测试语料使 G 为唯一正确来源，模型/词法索引按真实流程构建|实际本地模型下 G 进入最终主要 Top20，证据可续取|
|A3 去重和预算|图候选已在文本中、定义锚点重复、仅 1 个可用图候选、容量 20/40/44/48|文本保护不丢失，模型输入不超上限，不重复占位，余量状态准确|
|B1 二跳被饿死|A-B-C；第一跳同时有足够干扰关系和大量重复支持，C 只在二跳可达|第二跳获得自己的访问/输出机会；C 与必要桥接证据进入准入|
|B2 完整证据|两条边均有真实支持；随后分别移除中间证据、置 pending/rejected 或制造跨过滤边|不合格链不传播；成功链两条边均可追踪，无传递推断|
|B3 环路和超级节点|100+ 邻接边、A-B-A、反向边、多个根共享桥接节点|硬上限逐项满足，无无限循环；合法共享桥接不被全局去重误杀|
|B4 小上下文|终点能装入但完整链装不下|整条路径延期，有明确状态和续取信息，不计作完整两跳成功|
|C1 Graph 故障矩阵|准备前、一跳中、二跳后、锚点时、图计划校验、图包装、截止超时|允许降级时与图禁用文本基线等价；严格模式均返回稳定错误|
|C2 故障不污染|一条请求注入错误，下一条健康请求；失败和正常请求混排入队|无残留锚点/路径/缓存；后续健康图检索恢复；队列可继续服务|
|C3 不得降级的错误|非法请求、规范库/版本错误、缺失规范证据、调用取消|即使 allowDegraded=true 仍终止，不返回伪成功|
|C4 组合故障|Graph 与 dense 或 reranker 同时不可用|按现有可降级策略得到实际可用文本链路或明确失败；通道和原因无遗漏|
|D1 三入口|同一版本、同一参数经 JS/CLI/MCP 查询和续取|去除 request_id/时间后的证据与状态一致|
|D2 离线与交付|新包解压到新目录、断外网、模型本地加载|真实运行成功、来源续取可用、版本/哈希一致|

C1 的等价比较包括主要命题 ID/顺序、来源、条件/例外、议题组、deferred 和预算状态；排除随机请求 ID、计时、requested_profile 和合法降级轨迹。排序分数采用固定精度/数值容差，不以浮点位模式完全相同代替语义要求。候选和排名不同必须解释，不能一律用“近似”掩盖。

## 7. 质量评测与发布门槛

**7.1 固定对照。**

所有方法使用同一数据库、模型、policy、来源过滤、contextBudget、最终主要结果 limit=20 和相同机器。至少包含：

- L：当前正式版本默认链路，作为兼容性基线。
- T40：Graph 禁用，文本 40 重排，作为降级等价基线。
- T48：Graph 禁用，文本 48 重排，作为相同计算预算对照，排除“仅多看了 8 个文本”造成的假收益。
- G1：新准入＋一跳，40＋8。
- G2：新准入＋有界两跳，40＋8。
- G2-F：G2 注入 Graph 故障并允许降级，结果应对应 T40。
- 预登记成本备选：文本 40＋Graph 4，对照纯文本 44；不在看过验收集后反复调参数。

相同计算量对照 T48/T44 由评测脚本明确构造，不能被生产“保护文本最多 40”的默认规则偷偷缩成 40。

**7.2 数据分离。**

旧 240 题只做开发和回归；旧 24 题验收集已经暴露，不再称为新盲测。先制作新的开发补充集，再一次性冻结新验收集和参数：

- 开发补充：建议 60 题，覆盖两跳、定义/普通事实、条件/否定、领域外查询。
- 新验收：目标 120 题，其中两跳 60、普通事实/定义 30、条件/歧义/否定 15、领域外 15；至少 30 条不同的二跳证据链，变体按证据链分组。
- 每题先从原始来源标注必要命题、段落、条件/例外、可接受证据组，随后才运行方法。不能用 Graph 自己生成的边直接给自己判正确。
- 人工逐条确认两跳链与困难负例；未完成独立语义核验，只能报告自动化结果，不能通过正式质量门槛。
- 开发与验收按来源组/证据链隔离；原始知识库仍可被检索，这不是要求把答案来源从知识库删除。
- 如果实际语料不足以形成目标规模的合法独立链，记录实际规模和不确定性，不用同一链的换问法凑足数量。证据不足则保持新默认关闭。

**7.3 必报指标。**

1. graph_only 的发现、拟准入、实际送入模型、进入主要 Top20、被包装完整五段计数；graph_rescued 和定义锚点分开。
2. 候选证据覆盖、主要结果的 EvidenceRecall@20、完整已标注证据组@20。EvidenceRecall@20 定义为前 20 个主要命题所附证据覆盖的金标 passage_id 比例，按 passage_id 去重，辅助桥接命题排除；所有对照重新计算，不能直接沿用旧“段落排名 Top20”的数值。普通文本基线只要覆盖完整金标证据，也得到完整组分数，不要求它带 Graph 元数据。
3. 二跳终点新增正确证据@20；完整链的主要结果覆盖率；完整路径包装率。辅助桥接命题不能算成主要 Top20 召回。
4. contextBudget 内完整链覆盖作为另一个指标，明确包括辅助证据；不能单靠它证明等计算预算的检索收益。
5. 条件/方向/来源错误、pending 泄露、错误确定性表述、负例是否产生无依据的 Graph 增强。
6. 实际模型输入数、Graph 分阶段耗时、服务耗时、排队等待、端到端耗时、峰值内存、外网请求数。

**7.4 拟定硬门槛（数值是本方案的验收合同，不是已经测得的结果）。**

|维度|发布要求|
|---|---|
|机制|所有确定性验收通过；拟准入且预算内的 graph_only 进入实际模型的比例 100%；不得超过任一硬上限|
|可用性|可降级故障矩阵在 allowDegraded=true 下 100% 返回可验证基线；严格模式 100% 报错；所有全局完整性/取消用例均不得吞错|
|真实二跳收益|新验收两跳子集上，G2 的主要结果 Recall@20 相比 T48 和 G1 均至少增加 5 个百分点；按证据链分组的配对 bootstrap 95% 区间下界 >0|
|普通任务|普通事实/定义子集 Recall@20 相对 L、T48 的差值均不低于 -1 个百分点，95% 配对区间下界 ≥-2 个百分点；定义、条件、否定的关键正确性用例零退步|
|可追踪性|被声明完整的二跳路径 100% 含每条边的有效来源；任何引用损坏、审查状态泄露或把关联写成必然推论均阻断发布|
|负例|无查询实体根的领域外请求必须跳过新图扩展；已标注困难负例中，新增图命题/路径不得制造原基线没有的不相关主要结果或无依据关系。字面实体碰撞也必须覆盖；不以“检索返回了结果”认定答案正确|
|性能|同机交错运行至少 30 个固定查询×5轮，预热后 G2 端到端 p95 ≤L 的1.25倍且≤6秒；Graph p95≤50ms；进程峰值RSS≤2GiB；单请求重排≤48|
|交付|保留当前冷启动≤12秒门槛；在真实新解压目录执行离线 CLI/JS/MCP 和证据续取，交付清单哈希一致|

统计单位是独立证据链/来源组，而不是重复改写问题。报告效应大小与区间，不能把“差异不显著”解释成“相同”。如果区间不足以满足门槛，本轮结论为不确定/未通过，不临时降低标准。检索与证据包的通过仍不等于调用 Agent 的最终答案正确；当前产品只交付证据。

## 9. 发布与回滚

新配置以独立版本保存，默认先关闭新准入/两跳策略。M1 可先替换异常处理；M2/M3 先用于显式实验配置。M4/M5 全部通过后才切换默认。

回滚优先切回原检索策略/旧完整包，数据库与向量索引保持现有版本绑定。本次不改变图谱内容或 embedding，正常情况下无需重建向量索引。配置和程序不能跨版本任意混搭；响应契约新增字段和预算取值需同步更新 SDK/MCP/CLI，并验证旧请求仍可被处理。若新增响应字段无法做到兼容，应升级契约版本并保留旧读取路径。

任何阶段若只能证明“Graph 被执行”，而不能证明“正确的新证据进入主要结果”，都不能将 Graph 核心价值验收标为通过。
